# PLAN.md — Interview Trainer

Локальный голосовой тренажёр собеседований. Пользователь загружает документы (список вопросов, вакансию, резюме, кейсы). Программа озвучивает вопросы, принимает ответ голосом, распознаёт его и даёт короткий разбор: что не так и как поправить, или подтверждает, что ответ хороший.

---

## 1. Зафиксированные требования

| Параметр | Решение |
|---|---|
| ОС | Windows, RTX 3060 12 GB |
| LLM | Qwen через LM Studio (OpenAI-совместимый сервер, порт 1234) |
| Интерфейс | Локальная страница в браузере (`http://localhost:8000`) |
| Запись ответа | Кнопка «Начать» → говорю → кнопка «Стоп». Горячая клавиша: пробел |
| Фидбек | После **каждого** ответа: текстом подробно, голосом коротко |
| Поведение интервьюера | Задаёт **только вопросы из утверждённого списка**, без уточняющих вопросов |
| Источник вопросов | (а) готовый файл с вопросами; (б) генерация списка из вакансии, резюме и кейсов. Сгенерированный список пользователь просматривает и правит до старта |
| Язык | Русский; в речи много англоязычных терминов (SQL, ClickHouse, retention, A/B, p-value) |

**Не делаем:** облачные API, потоковый диалог в реальном времени, уточняющие вопросы, БД, многопользовательский режим, авторизацию.

## 2. Стек

| Слой | Технология | Где работает |
|---|---|---|
| Backend | Python 3.11, FastAPI, uvicorn | CPU |
| Frontend | Один `index.html` + `app.js` + `style.css`, без фреймворков | браузер |
| LLM | LM Studio, клиент `openai` (python) | GPU |
| STT (основной) | **GigaAM v3 e2e RNNT** через пакет `onnx-asr` (onnxruntime) + Silero VAD для длинных ответов | CPU |
| STT (запасной, этап 6) | `faster-whisper` large-v3-turbo, int8 | CPU |
| TTS | **Silero TTS v5** (`v5_5_ru` или актуальная v5-модель), спикер настраивается | CPU (torch CPU) |
| Чтение документов | `python-docx`, `pypdf`, md/txt нативно | CPU |
| Нормализация текста для TTS | `num2words` (ru) + свой глоссарий | CPU |
| Хранение | JSON и Markdown в `data/` | диск |

### Выбор LLM
- **Старт: Qwen3-14B Instruct, Q4_K_M** (~9 GB). Даёт лучшее качество разбора на русском.
- **Запасной вариант: Qwen3-8B, Q4_K_M/Q6_K**, если 14B не влезает с нужным контекстом или работает медленно.
- Если в каталоге LM Studio есть более новая Qwen близкого размера (до ~14B), её тоже прогоняем на этапе 0. Модели на 27B+ в 12 GB с контекстом нормально не поместятся.
- Thinking-режим Qwen3 по умолчанию **выключен** (`/no_think`) ради скорости. Флаг в конфиге позволяет включить его для ревьюера, если вырастет качество.
- Контекст в LM Studio: 8–12k. Если не хватает VRAM, включить квантизацию KV-кэша (Q8) в настройках загрузки модели.

### Бюджет ресурсов (оценка, уточняется на этапе 0)
- VRAM: LLM ~9 GB + KV-кэш ~1–2 GB. STT и TTS видеопамять не занимают.
- RAM: GigaAM ~0.3 GB, Silero ~0.2 GB, torch ~1 GB.
- Целевые задержки: распознавание 60 с речи ≤ 5 с; разбор ответа ≤ 15 с; озвучка фразы ≤ 1 с.

## 3. Архитектура

```
Браузер (index.html)
  ├─ запись микрофона (AudioWorklet) → WAV 16 kHz mono PCM16
  ├─ POST /api/sessions/{sid}/transcribe  → текст ответа
  ├─ POST /api/sessions/{sid}/review      → JSON-фидбек
  └─ POST /api/tts                         → WAV → <audio>

FastAPI (app/main.py)
  ├─ stt.py       GigaAM (+VAD) → текст → глоссарий (обратные замены)
  ├─ llm.py       клиент LM Studio, JSON-ответы, очистка <think>
  ├─ tts.py       нормализация (числа, латиница) → Silero → WAV
  ├─ documents.py разбор md/txt/docx/pdf, парсинг вопросов
  ├─ questions.py генерация списка вопросов из вакансии, резюме и кейсов
  ├─ review.py    разбор ответа
  ├─ session.py   состояние сессии, попытки, переходы
  └─ report.py    итоговый отчёт по сессии
```

### config.yaml (начальный)
```yaml

  base_url: http://localhost:1234/v1
  model: auto            # auto = первая загруженная модель из /v1/models
  temperature: 0.3
  max_tokens: 1200
  disable_thinking: true # добавлять /no_think, вырезать <think>…</think>
  timeout_s: 120

  engine: gigaam         # gigaam | whisper
  model: gigaam-v3-e2e-rnnt
  use_vad: true
  max_answer_seconds: 300

  engine: silero
  model: v5_5_ru
  speaker: eugene        # aidar | baya | kseniya | xenia | eugene
  sample_rate: 48000
  speak_feedback: true

  shuffle: false
  questions_per_session: 0   # 0 = все

```

### glossary.yaml
Две таблицы:
- `tts`: как произносить латиницу, например `ClickHouse: кликхаус`, `A/B: эй-би`, `SQL: эс-кью-эль`, `p-value: пи-вэлью`, `retention: ретеншн`.
- `stt_fix`: исправления типичных ошибок распознавания, например `клик хаус → ClickHouse`, `эй би тест → A/B-тест`.

Глоссарий пополняется по ходу использования. Ревьюер получает пометку, что текст — автоматическая расшифровка речи и ошибки в терминах не являются ошибками кандидата.

## 4. Пользовательский сценарий и экраны

### Экран «Подготовка»
1. Создать или выбрать собеседование: название, например «Т2 — продуктовый аналитик».
2. Загрузить документы в четыре слота: **Вопросы**, **Вакансия**, **Резюме**, **Кейсы** (md/txt/docx/pdf, можно несколько файлов в слоте).
3. Источник вопросов:
   - «Из файла»: парсер извлекает вопросы и показывает список;
   - «Сгенерировать»: LLM строит N вопросов (по умолчанию 12) по вакансии, резюме и кейсам;
   - можно совместить: вопросы из файла плюс догенерация.
4. Редактор списка: править текст, удалять, менять порядок, добавлять, смотреть «что проверять» у каждого вопроса. Кнопка «Утвердить» сохраняет `questions.json`.

### Экран «Собеседование»
- Слева: список вопросов со статусами (не начат / ok / доработать / переделать / пропущен).
- По центру: текст текущего вопроса (по умолчанию скрыт, кнопка «Показать текст»), большая кнопка микрофона с состояниями:
  `Готов` → `Запись 00:42` → `Распознаю…` → `Анализирую…` → `Озвучиваю`.
- Под ней: расшифровка ответа, затем карточка фидбека:
  вердикт и оценка 1–5, сильные стороны, что не так, как исправить, скелет улучшенного ответа.
- Кнопки: «Повторить вопрос» (озвучить заново), «Ответить ещё раз» (новая попытка, старые сохраняются), «Пропустить», «Следующий вопрос», «Завершить».
- Переключатели: «Озвучивать фидбек», «Показывать текст вопроса».
- Пробел запускает и останавливает запись, когда фокус не в поле ввода.

### Поток одного вопроса
1. Интервьюер озвучивает вопрос: текст из списка → TTS. **LLM на этом шаге не вызывается**, это экономит время.
2. Пользователь жмёт «Начать», отвечает, жмёт «Стоп».
3. `/transcribe` возвращает текст, он сразу появляется на экране.
4. `/review` возвращает JSON-фидбек: карточка на экране, `spoken_summary` озвучивается.
5. Пользователь выбирает «Ответить ещё раз» или «Следующий вопрос».

### Завершение
LLM собирает фидбеки по всем вопросам в `report.md`: общая оценка, 3 главные слабые зоны, вопросы для повторной тренировки, рекомендации. Отчёт виден в UI и сохраняется на диск.

## 5. LLM: промпты и форматы

Все вызовы возвращают JSON. Основной путь — `response_format` с `json_schema` (LM Studio поддерживает structured output; проверить на этапе 0). Запасной путь — извлечь JSON из текста, провалидировать pydantic, при ошибке до 2 повторов с сообщением об ошибке.

### 5.1 Профиль кандидата (`candidate_profile.md`)
Вызывается один раз при загрузке резюме и кейсов. Результат сжимается до ≤ 1500 токенов и кэшируется в `profile.md`. Содержит: опыт, стек, ключевые кейсы **с реальными цифрами из документов**, сильные темы. Требование к промпту: не выдумывать цифры, использовать только то, что есть в документах.

### 5.2 Генерация вопросов (`generate_questions.md`)
Вход: вакансия, профиль кандидата, количество, желаемый микс категорий.
Категории: `experience` (о кейсах из резюме), `technical` (SQL, статистика, A/B, метрики), `product_case` (продуктовые кейсы и задачи на оценку), `behavioral`, `motivation`.
Выход:
```json
{"questions": [
  {"id": "q01", "text": "...", "category": "technical",
   "what_to_check": ["...", "..."],
   "expected_points": ["...", "..."]}
]}
```

### 5.3 Разбор ответа (`review.md`) — главный промпт
Вход: вопрос, `what_to_check`, `expected_points`, профиль кандидата, вакансия (кратко), расшифровка ответа, длительность ответа.
Роль: строгий, но конструктивный интервьюер-наниматель на позицию из вакансии.
Критерии оценки:
- ответил ли на заданный вопрос;
- структура (для поведенческих и про опыт — STAR: ситуация, задача, действия, результат);
- конкретика и цифры; для кейсов — совпадение с цифрами из профиля, без «примерно»;
- техническая корректность;
- лишнее: вода, уход от темы, слишком длинный или слишком короткий ответ.
Правила: не придираться к оговоркам и ошибкам распознавания; если ответ хороший, так и сказать, без выдуманных замечаний; советы конкретные, применимые к этому ответу.
Выход:
```json
{
  "verdict": "ok | improve | redo",
  "score": 1,
  "strengths": ["..."],
  "issues": ["..."],
  "how_to_fix": ["..."],
  "improved_outline": "скелет сильного ответа, 3–6 пунктов",
  "spoken_summary": "2–3 предложения, ≤ 60 слов, для озвучки"
}
```

### 5.4 Итог сессии (`session_summary.md`)
Вход: все вопросы и фидбеки. Выход: Markdown-отчёт по шаблону из раздела 4.

### Технические требования к `llm.py`
- `get_model()`: при `model: auto` — первая модель из `/v1/models`. Если сервер LM Studio не отвечает или модель не загружена, понятная ошибка на русском в UI.
- Удаление блоков `<think>…</think>` из ответа.
- Логирование каждого вызова (промпт, ответ, время, токены) в `data/logs/llm.jsonl` для отладки промптов.

## 6. Аудио

### Запись (frontend)
- `getUserMedia({audio: {echoCancellation: true, noiseSuppression: true}})`.
- `AudioWorklet` собирает float32-сэмплы, на «Стоп» — ресемплинг в 16 kHz mono и кодирование WAV PCM16 прямо в JS. ffmpeg не нужен.
- Лимит длины ответа из конфига; за 30 с до лимита — предупреждение.
- Пока играет TTS, кнопка записи заблокирована.

### STT (`stt.py`)
- Интерфейс `transcribe(wav_bytes) -> {text, seconds, elapsed}`, реализации `GigaAMEngine` и (позже) `WhisperEngine`.
- WAV → numpy **float32** в диапазоне [-1, 1], 16 kHz. GigaAM на int16 молча возвращает пустую строку.
- GigaAM рассчитан на короткие фрагменты (~до 25–30 с), а ответы на собеседовании длятся 1–3 минуты. Поэтому длинные записи режем через **Silero VAD** по паузам (в `onnx-asr` есть встроенная связка модели с VAD), сегменты не короче ~5–10 с. Слишком мелкая нарезка ухудшает качество.
- После распознавания применить `glossary.stt_fix`.
- Модель загружается один раз при старте сервера (прогрев).

### TTS (`tts.py`)
- Интерфейс `synthesize(text) -> wav_bytes`.
- Перед синтезом: числа → слова (`num2words`, ru), латиница → глоссарий; если в глоссарии нет — транслитерация как запасной вариант.
- Длинный текст режется по предложениям (Silero ограничивает длину входа), куски склеиваются.
- Кэш на диск по хэшу текста и голоса: вопросы при повторе озвучиваются мгновенно.
- Лицензия Silero — CC BY-NC: для личного использования подходит.

## 7. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | статус LM Studio (и имя модели), STT, TTS |

## 8. Этапы

Каждый этап заканчивается проверкой пользователем. Без подтверждения следующий этап не начинаем.

### Этап 0. Окружение и проверка компонентов
- Каркас репозитория, `.venv`, `requirements.txt`, `.gitignore`, `config.yaml`, `glossary.yaml`.
- `scripts/check_lmstudio.py`: список моделей, скорость в токенах/с, проверка `/no_think`, проверка `json_schema`, тестовый разбор фиктивного ответа на русском.
- `scripts/check_stt.py`: распознать WAV-файл или записать с микрофона N секунд (`sounddevice`); вывести текст и время. Проверить на коротком (10 с) и длинном (90 с) ответе с терминами.
- `scripts/check_tts.py`: озвучить фразу с числами и терминами, сохранить WAV, вывести время синтеза.
- **Готово, когда:** все три скрипта работают, есть таблица задержек, выбрана модель LLM (14B или 8B) и размер контекста.
- **Проверка пользователем:** послушать TTS; надиктовать 2–3 ответа со своими терминами и оценить распознавание.

### Этап 1. Минимальный голосовой цикл (MVP)
- FastAPI, раздача `static/`, `/api/health`, `/api/tts`, `/transcribe`, `/review`.
- Страница: 3 захардкоженных вопроса, кнопка записи, расшифровка, карточка фидбека, озвучка `spoken_summary`.
- Сессия в памяти, без сохранения на диск.
- **Готово, когда:** полный цикл «вопрос голосом → ответ → текст → фидбек голосом» работает в браузере.
- **Проверка:** пройти 3 вопроса, оценить скорость и адекватность фидбека.

### Этап 2. Документы и список вопросов
- Сущность «собеседование», хранение в `data/interviews/<slug>/`.
- Загрузка документов по слотам, разбор md/txt/docx/pdf.
- Парсер вопросов из файла: нумерованные и маркированные списки, заголовки `##`, строки с `?`; блок «Критерии:» под вопросом идёт в `what_to_check`. Покрыть юнит-тестами на 4–5 форматах.
- Экран «Подготовка» с редактором списка и кнопкой «Утвердить».
- Сохранение сессий, попыток и аудио на диск.
- **Готово, когда:** загруженный файл с вопросами превращается в сессию, после перезапуска сервера всё на месте.

### Этап 3. Качество фидбека
- Профиль кандидата (5.1) с кэшированием.
- Боевой промпт ревьюера (5.3), structured output, валидация, повторы.
- Глоссарий в STT и TTS, пометка про ошибки распознавания в промпте.
- `scripts/eval_review.py`: набор 8–10 эталонных пар «вопрос + ответ + ожидаемый вердикт» (хорошие, средние, слабые, ответ мимо вопроса, ответ без цифр). Прогон по моделям и версиям промпта, таблица совпадений вердиктов и времени.
- **Готово, когда:** на эталонном наборе вердикты совпадают не меньше чем в 8 случаях из 10, хорошие ответы не получают выдуманных замечаний.
- **Проверка:** пользователь сам оценивает фидбек на своих настоящих ответах.

### Этап 4. Генерация вопросов из вакансии, резюме и кейсов
- Промпт 5.2, выбор количества и микса категорий в UI.
- Режим «файл + догенерация».
- **Готово, когда:** по реальной вакансии получается список, который пользователь признаёт похожим на настоящее собеседование и правит не больше 30% вопросов.

### Этап 5. Отчёт и история
- `/finish` → `report.md` (раздел 4), просмотр в UI.
- История сессий собеседования: даты, средняя оценка, динамика по вопросам.
- Режим «Тренировать слабые»: новая сессия только из вопросов с вердиктом `improve`/`redo` в прошлых сессиях.

### Этап 6. Доводка
- `start.bat`: активирует `.venv`, проверяет доступность LM Studio (если нет — подсказка запустить сервер), стартует uvicorn, открывает браузер.
- Страница настроек: голос TTS, движок STT, модель, флаг thinking.
- Опционально: `WhisperEngine` (faster-whisper large-v3-turbo, CPU int8) как альтернатива для ответов с большим количеством английского.
- `README.md` с установкой с нуля.

## 9. Риски и что с ними делать

| Риск | Митигация |
|---|---|
| GigaAM искажает английские термины | `stt_fix` в глоссарии; пометка в промпте ревьюера; Whisper как альтернатива (этап 6) |
| Silero плохо читает латиницу и цифры | `num2words` + глоссарий `tts` |
| 14B не помещается с нужным контекстом | KV-кэш Q8, контекст 8k, переход на 8B |
| Фидбек слишком общий или придирчивый | Эталонный набор `eval_review.py`, `expected_points` у вопросов, правило «не выдумывать замечания» |
| Долгие ответы (2–3 мин) медленно распознаются | VAD-нарезка, замер на этапе 0; при необходимости показывать прогресс |
| LM Studio не запущен или модель не загружена | `/api/health` + понятное сообщение в UI и в `start.bat` |
| Микрофон: эхо от TTS | Блокировка записи во время воспроизведения, echoCancellation |

## 10. Definition of Done (вся программа)
- Запуск одним `start.bat` при запущенном LM Studio.
- Загрузка вопросов или генерация по вакансии, правка, утверждение.
- Голосовое прохождение собеседования с фидбеком после каждого ответа: текст и голос.
- Повторные попытки, пропуск, итоговый отчёт, история и режим «Тренировать слабые».
- Всё работает без интернета после первичной загрузки моделей.
