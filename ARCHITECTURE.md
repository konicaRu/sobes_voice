# ARCHITECTURE

## Назначение
Локальный голосовой тренажёр собеседований. Подробная архитектура и этапы: [PLAN.md](PLAN.md). Правила работы: [CLAUDE.md](CLAUDE.md).

## Структура
Целевая структура описана в PLAN.md, раздел 3. Фактическое состояние (после этапа 2):

- `PLAN.md`: план работ и архитектура.
- `CLAUDE.md`: правила работы агента.
- `project-starter.md`: резервная копия общего стартового чек-листа.
- `MEMORY.md`: журнал сессий.
- `app/`: бэкенд FastAPI.
  - `main.py`: роуты и фабрика `create_app` (движки и хранилище внедряются, в тестах подменяются); потоковое чтение тела с лимитом.
  - `config.py`, `models.py` (Question, Interview, Attempt, Session, слоты документов).
  - `storage.py`: JSON и файлы в `data/interviews/` (собеседования, документы, вопросы, сессии, аудио); защита от выхода за папки.
  - `documents.py`: извлечение текста из md/txt/docx/pdf, безопасные имена файлов, лимиты (5 МБ, 50 МБ в распакованном docx, 300 страниц pdf).
  - `questions.py`: парсер списка вопросов (нумерованные и маркированные списки, заголовки, строки с «?», критерии; режим заголовков для конспектов) и склейка списков из нескольких файлов.
  - `stt.py` (GigaAM, нарезка по паузам, приведение к 16 кГц, выравнивание громкости), `tts.py` (Silero, кэш WAV на диске), `text_norm.py` (глоссарий, числа, транслитерация латиницы).
  - `llm.py` (клиент LM Studio, JSON-схема, повторы, температура на вызов, лог `data/logs/llm.jsonl`).
  - `review.py` + `prompts/review.md`: разбор ответа. Модель сначала формулирует темы вопроса и ответа и решает, по теме ли ответ (при сомнении решает короткий арбитр `TopicCheck`; ответ мимо вопроса получает 1 из 5 по шаблону), затем заполняет `coverage` (ключевые пункты с цитатами из ответа), потом ставит `score` 1–5 и пишет замечания. Вердикт считает код из оценки (4–5 ok, 3 improve, 1–2 redo). Код проверяет цитаты по расшифровке, ограничивает оценку долей нераскрытых пунктов, у хорошего ответа со всеми пунктами убирает замечания, списки режет до 3 (сильные стороны до 2), озвучка до 45 слов.
  - `report.py` + `prompts/session_summary.md`: итоги сессии. Код считает статусы вопросов (не начат / без разбора / хорошо / доработать / переделать / пропущен), оценки, среднюю, список «повторить», историю с матрицей «вопрос × сессия» и слабые вопросы (последний вердикт доработать/переделать среди вопросов текущего утверждённого списка). Модель пишет только качественный итог (общая оценка, до 3 слабых зон, до 4 рекомендаций); латинские термины, которых нет во входных данных, из её текста отбрасываются. Отчёт сохраняется как `report.json` и `report.md`.
  - `jobs.py`: `JobTracker`, фоновые задачи со статусом (состояние, проценты, сообщение, результат, секунды); ключ `profile:<id>` и `questions:<id>`.
  - `generation.py` + `prompts/generate_questions.md`: генерация вопросов из вакансии (до 3000 символов) и профиля (до 4500) по категориям `experience/technical/product_case/behavioral/motivation`; лишние и повторяющиеся вопросы отбрасываются, критерии режутся до 4 пунктов. Температура 0.7.
  - `profile.py` + `prompts/candidate_profile.md`: профиль кандидата из резюме и кейсов (кэш `profile.md`, правится в UI). Профиль, начало вакансии, эталонный ответ вопроса и список терминов из глоссария добавляются в каждый разбор.
- `static/`: страница без фреймворков, ES-модули. `index.html`, `style.css`, `main.js` (связка экранов), `ui.js` (общие помощники), `home.js` (список собеседований), `prepare.js` (документы по слотам и редактор вопросов), `interview.js` (голосовой цикл, список вопросов со статусами, пропуск), `report.js` (завершение и отчёт), `history.js` (история и динамика), `recorder-worklet.js` (запись через AudioWorklet, WAV 16 кГц mono).
- `tests/`: pytest, 295 тестов; STT, TTS и LLM замоканы.
- `.claude/settings.json`: PostToolUse-хук (после правки `.py` прогоняет pytest через `scripts/hooks/pytest_on_py_edit.py`, лог в `data/logs/hook.log`).
- `.claude/skills/git-save/`: скилл `/git-save` (тесты, pyright, обновление MEMORY/ARCHITECTURE/README, коммит, пуш); запускается только пользователем.
- `pyrightconfig.json`: настройки Pyright; корректно работает из CLI в корне проекта (в редакторе LSP-плагин корень выбирает сам, оттуда шум «не удаётся разрешить импорт»).
- `config.yaml`, `glossary.yaml`: настройки и глоссарий.
- `requirements.txt`: закреплённые зависимости (torch только CPU).
- `scripts/check_lmstudio.py`, `check_stt.py`, `check_tts.py`: проверка компонентов (этап 0); `scripts/hooks/`: скрипт хука.
- `scripts/eval_review.py` + `scripts/eval/review_cases.json`: оценка качества разбора на 10 эталонных парах (синтетические, без личных данных). Опции: `--prompt`, `--model`, `--runs N` (стабильность), `--only ID`. Результаты в `data/eval/` (`last.md` читается глазами).

## Данные на диске (`data/`, в .gitignore)
```
data/interviews/<id>/
  interview.json
  docs/<questions|vacancy|resume|cases>/<файлы>
  questions.json                     # утверждённый список (текст, критерии, эталонный ответ)
  profile.md                         # профиль кандидата (кэш LLM, правится пользователем)
  sessions/<ГГГГММДД-ЧЧММСС>/
    session.json                     # вопросы-снимок, попытки, разборы, пропущенные, время завершения
    audio/q01_a1.wav
    report.json, report.md           # итоговый отчёт (после «Завершить»)
data/cache/tts/, data/logs/, data/check/
```
`<id>` — латинский slug из названия (`t2-produktovyi-analitik`), id сессии: `<id>__<ГГГГММДД-ЧЧММСС>`.

## Команды (PowerShell, из корня проекта)
```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\check_tts.py
.\.venv\Scripts\python.exe scripts\check_stt.py --record 10
.\.venv\Scripts\python.exe scripts\check_stt.py --wav data\check\tts.wav
.\.venv\Scripts\python.exe scripts\check_lmstudio.py
.\.venv\Scripts\python.exe scripts\eval_review.py                # качество разбора, нужен LM Studio; --runs 3 для стабильности
.\.venv\Scripts\python.exe -m pytest -q
pyright                                   # из корня проекта, должно быть 0 errors
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000   # затем http://localhost:8000
```

Модели грузятся при старте сервера (около 15 с). Сессии, попытки и аудио сохраняются на диск сразу, после перезапуска всё на месте.

## Отклонения от PLAN.md
- STT: вместо Silero VAD длинные ответы режутся по паузам на куски ~20 с (`chunk_seconds`). Причина: VAD терял речь на тихих записях.
- TTS: модель `v5_6_ru` (в плане `v5_5_ru`), темп через SSML (`tts.rate`).
- LLM: `qwen2.5-14b-instruct-1m` Q4_K_M, контекст 8192 (в плане Qwen3-14B).
- Разбор (этап 3): модель не возвращает `verdict` (в PLAN.md был), вердикт считается из `score`; добавлено поле `coverage` с цитатами и проверка цитат в коде. Причина: Qwen2.5-14B Q4 писал «ok» при оценке 2 и придирался к тому, что в ответе есть.
- API (этап 2): файлы загружаются сырым телом запроса (`?slot=&filename=`), а не multipart; нечитаемый файл отклоняется до сохранения. `POST /api/sessions` этапа 1 убран, сессия создаётся через `POST /api/interviews/{id}/sessions` только при утверждённом списке. `/next` нет: порядок вопросов ведёт клиент, на сервер уходят только пропуск и завершение.
